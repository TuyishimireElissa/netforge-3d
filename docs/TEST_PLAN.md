## Reproducible entry point and CI gates
`python3 -m tools.verify --report-dir artifacts/verification-local` records `passed`, `failed`, `blocked` or `skipped` with stage logs and `report.json`. The default local policy fails Python/configuration failures but reports missing Godot as blocked. `--require-godot` turns any engine block/skip into a failed overall exit code; Windows CI uses it. `--download-godot` attempts the pinned official release (no third-party mirrors). Installed Godot must report version 4.2.2. Engine stages are ordered: headless editor import, main scene startup, scripted integration with a real loopback backend fixture; startup/script engine errors fail the stage even if exit code is 0.

`game/tests/smoke.gd` is an authored (not yet executed here) headless integration test for movement/camera update, equipment IDs/crosshair ray, cable state consistency, terminal/port security, missions A/B, checkpoint/reset/restore and disconnection. It is **not** a Windows GUI automation test: rendered appearance, physical pointer interaction and accessibility still require graphical verification. The workflow file is not evidence of a passing run; see GitHub checks for actual status.
