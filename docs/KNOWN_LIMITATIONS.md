# Known limitations / blockers (2026-10-15)
- Godot executable absent **in this sandbox**. Hosted [CI run 38756303805](https://github.com/TuyishimireElissa/netforge-3d/actions/runs/38756303805) passed Linux headless editor import, scene startup and simulated mission integration; Windows passed scene startup and mission integration, but Godot 4.2.2 headless **editor import exits 1 without an error message** on the hosted Windows runner. That stage is explicitly BLOCKED, not passed. No engine test here has rendered the GUI or measured mouse interaction, frame rate or Windows 10/8 GB performance. Attempted the compatible official **4.2.2** Linux release via GitHub and API on 2026-10-15; both redirect to blocked objects/release-assets.githubusercontent.com hosts (TLS failure). The official source tarball was fetched to /tmp but a local build is blocked by missing `pkg-config` and system development headers/libraries; no compiled engine exists here. Hosted Windows and Linux runners both downloaded the official 4.2.2 release and verified SHA512; the executed CI results above are the evidence, not the workflow file alone. No web preview: this is a desktop Godot project.
- Prototype GUI still has static project title/host/port, no control remapping, graphics/audio menu, topology map, packet animation, furniture/wall collisions, screen reader support or save confirmation. Godot scene script remains monolithic; refactoring and graphical usability testing remain.
- Only two endpoints and two access ports. No real packets/PCAP, ARP cache, MAC aging, STP/loop, trunks/802.1Q frames, IPv6, routing, DHCP, DNS, firewall, wireless or TLS behavior. Ping only same subnet; router remains VISUAL ONLY. CLI is vendor-inspired, not vendor equivalent.
- SQLite v1 stores **one built-in simulated lab** and up to 20 explicit checkpoints; no profiles, multi-user progress, scheduling, upgrade from earlier schema, automatic backups or OS/VM/tool snapshots. Reset keeps checkpoints but clears active work. The headless console and `--ephemeral` bridge have no durable save; their `write memory` lasts only until process exit. DB file is not encrypted; use a trusted local user account.
- Mission A/B JSON is executable for registered state/evidence criteria and weighting, but scenario generation/initial topology is still fixed, prose tasks do not automatically trigger actions, and there is no printable completion/incident report or persistent learner profile. A completed state after restore is a simulated state, not proof of real network access.
- No real provider, range, resource/egress isolation, real tool integration or appliance images. Being able to run `ip`/`ping` on the host does not mean this app executes them. Do not use the simulator as a cyber range.
- Loopback token bridge is trusted desktop only; no multi-user auth, rate limits, HTTPS, remote labs or tamper-resistant audit. SQLite lives under the local user home by default. CI, Godot and Windows 10 smoke, load/resource testing are outstanding.
- The Python wheel excludes Godot project files; it is not a packaged Windows game installer. The headless smoke cannot prove full graphical mouse selection/appearance or performance on an 8 GB Windows 10 PC.
